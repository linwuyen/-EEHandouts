第 1 課 · ADC 量化

4096 個 code，最大編號是 4095

理想 12-bit ADC 一共有 212 = 4096 個量化區間，但編號從 0 起算，因此最大輸出 code 是 4095。這兩個數字不能放到同一個分母而不說明假設。

本站共用計算核心採用LSB = Vref / 2^Ncode = clamp(floor(Vadc / LSB), 0, 2^N - 1)

舊課程採 Vref / (2^N−1) 並四捨五入，屬於端點對映近似；本站將它保留為「端點顯示步距」的概念，不當成量化 LSB 或 ADCRESULT 的實際轉換規則。

數值驗證 · 3.3 V / 12-bit

LSB = 3.3 / 4096 = 0.805664 mV。Vadc = 1.650 V → code 2048；Vadc ≥ 3.3 V → 最高 code 4095。最高 code 不能用來證明未曾飽和。

理解題：4095 與 4096 哪個是滿刻度 code？

4095 是最大 code；4096 是不同 code 的總數。將分母 4095 用於端點比例時，不能再把該結果當成 4096 區間的理想量化 LSB。

第 2 課 · Shunt 與放大器

ADC 不讀安培，只讀輸入腳位的電壓

電流穿過精密分流電阻產生壓差，再由放大器放大。量測方向、輸入共模範圍、Kelvin 走線、功耗與噪聲都可能限制電路，不是調大 Gain 就能改善解析度。

Vshunt = I × RshuntVsignal = Vshunt × GainPshunt = I_rms² × Rshunt
數值驗證 · 30 A、5 mΩ、Gain 8.2

Vshunt = 30 × 0.005 = 0.150 V；放大訊號 = 1.230 V。若是連續 30 A RMS，Shunt 損耗 = 4.5 W，不可忽略封裝溫升與額定。

RC 抗雜訊濾波會增加相位延遲；ADC sample-and-hold 在取樣期間也會向前級取電荷。請將 R/C、放大器輸出阻抗與 acquisition window 一起估算，而非只看靜態增益。

理解題：Gain 從 8.2 提高到 20，一定比較好嗎？

不一定。相同輸入電流的輸出電壓會更高，可能先碰到 0/Vref 或放大器輸出擺幅上限；同時必須驗證噪聲、頻寬和穩定時間。

第 3 課 · 雙向 Offset

把零電流移到 ADC 動態範圍中間

單端 ADC 的輸入下限通常不能接受負電壓。將零電流偏移到 1.65 V，正負方向的訊號便分別朝上限與下限移動；Offset 漂移仍需另行校準。

Vadc = I × Rshunt × Gain + OffsetI = (Vadc − Offset) / (Rshunt × Gain)
數值驗證 · Rshunt=5 mΩ、Gain=8.2、Offset=1.65 V

I = 0 A → 1.65 V、2048 code；I = −20 A → 0.83 V、1030 code；I = +20 A → 2.47 V、3065 code。理想可量邊界約 ±40.24 A，但實際設計必須預留容差及瞬態裕度。

理解題：Offset = 0 V 時能否測到 −20 A？

不能直接用此單端 0…3.3 V 模型讀取負電壓。該訊號會低於量測範圍；回傳 0 code 不代表真實電流恰好是 0 A。

第 4 課 · 母線分壓與元件應力

把高電壓縮小，但不要只確認 ADC 沒超量程

分壓的兩個電阻必須同時考慮比值誤差、功耗、元件實際 working voltage、突波與 PCB 佈線。高阻值電阻鏈可能增加 ADC 取樣電容的充電時間，分壓比例正確不代表取樣結果正確。

Vadc = Vbus × Rbot / (Rtop + Rbot)Idiv = Vbus / (Rtop + Rbot)Ptop = Idiv² × Rtop
數值驗證 · Vbus 800 V、Rbot 8.25 kΩ

Rtop = 2 MΩ 時，Vadc ≈ 3.286 V，幾乎沒有上限裕度；Rtop 改為 2.45 MΩ 時，Vadc ≈ 2.685 V。但 800 V 仍分攤在高阻值電阻鏈上，必須逐顆檢查耐壓、功率及失效方式。

理解題：四顆等值 Rtop 串聯，就保證安全嗎？

不能。理想條件下電壓平均分配，但單顆的額定工作電壓、爬電距離、分布電容、surge 及失效模式都要另外驗證。

第 5 課 · Firmware Scaling

從 ADC code 恢復電流及母線電壓

若類比路徑已確認可用，韌體才把整數 code 換算為工程單位。零電流校準、ADC offset/gain error、ADCRESULT 的有效時序，均不能從一個理想係數自動推得。

K_I = (Vref / 2^N) / (Rshunt × Gain) [A/count]Current_A ≈ (code − zeroCount) × K_IK_V = (Vref / 2^N) × (Rtop + Rbot) / Rbot [V/count]Bus_V ≈ code × K_V
數值驗證 · 3.3 V、12-bit、5 mΩ、Gain 8.2

K_I ≈ 0.01965034 A/count，zeroCount = 2048。量化後再反推有約一個 LSB 的不確定性，因此數值與理想 20.000 A 不會完全相等。只有完成量測和校準，係數才可能作為產品韌體的參數。

實際 C2000 時序：以 F28004x 的 100 MHz SYSCLK 為例，取樣時間依 SOC 的 ACQPS 設定；ACQPS = 7 對應 8 個 SYSCLK 週期 = 80 ns。TI 的 75 ns 最短取樣窗條件限定低源阻抗（Rs ≤ 50 Ω），高阻抗或 RC 設計需另行做 settling 分析。此處不產生可直接燒錄的 register configuration。F28004x 的 ADC 是 12-bit；工具其他位元數僅為通用理想模型。
理解題：ADCRESULT=4095 可以直接表示精確的 3.3 V 嗎？

不行。最高 code 可能已包含飽和、量化與參考電壓誤差；還要檢查 ADC conversion/EOC 時序，以及取樣網路的 settling。
